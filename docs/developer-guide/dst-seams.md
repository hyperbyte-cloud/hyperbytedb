# DST seams (`dst` branch)

The `dst` branch builds HyperbyteDB inside the deterministic simulation
testing rig (`hyperbytedb-sim`) with `RUSTFLAGS="--cfg madsim"`. Every change
the rig needs in this repo is a `#[cfg(madsim)]` environment seam or a
zero-cost trait seam; without `--cfg madsim` the build is the production
build. Replication, sharding, flush, Raft and startup logic are never forked
for the sim.

One line per seam: file — what — why.

- `hyperbytedb/Cargo.toml` — `tokio` is `madsim-tokio` (renamed to `tokio`) — re-exports real tokio normally; under `cfg(madsim)` swaps in madsim's deterministic runtime, time and network.
- `hyperbytedb/Cargo.toml` — `tikv-jemallocator` moved to `[target.'cfg(not(madsim))'.dependencies]` — jemalloc's background purge threads are a nondeterminism source; the sim uses the system allocator.
- `hyperbytedb/Cargo.toml` — `[lints.rust] unexpected_cfgs` declares `cfg(madsim)` — keeps `-D warnings` clean for the new cfg.
- `hyperbytedb/src/main.rs` — `#[global_allocator]` jemalloc only under `not(madsim)` — pairs with the dependency gate above.
- `hyperbytedb/src/lib.rs` — `#![cfg_attr(madsim, allow(deprecated))]` — madsim-tokio deprecates `spawn_blocking` (it runs the closure as a simulated task); silences ~40 warnings at RocksDB/chDB call sites.
- `hyperbytedb/src/application/runtime/control.rs` — `install()`/`shutdown()` are no-ops under `cfg(madsim)`; `RUNTIME`/`CONTROL_WORKERS` gated out — no second runtime can exist in the sim, so control work runs on the caller's runtime (the documented no-runtime path).
- `hyperbytedb/src/application/runtime/control.rs` — `spawn_on` re-panics with `panic!` under `cfg(madsim)` — madsim's `JoinError` has no `into_panic`.
- `hyperbytedb/src/adapters/cluster/peer_client.rs` — `wait_for_inflight` uses `timeout(deadline - now)` under `cfg(madsim)` — madsim-tokio has no `time::timeout_at`.
- `hyperbytedb/src/ports/serve_transport.rs` — `ServeTransport` port (`serve(kind, addr, router, shutdown)`, `stopped(kind, shutdown)` defaulting to "wait for the flip") and `ListenerKind { Main, Control }` — zero-cost trait seam: how a node's routers are exposed. Replaces Task 1's `cfg(madsim)` "bind nothing, wait for ctrl-c" branch in `server.rs`.
- `hyperbytedb/src/adapters/http/tcp_serve_transport.rs` — `TcpServeTransport`, built only under `not(madsim)`: the TCP/TLS binding moved from `server.rs` (TLS file checks, `axum_server` with 10 s graceful shutdown, plain `axum::serve` with `nodelay`, control listener spawned on the control runtime and never drained) — production transport; `madsim_tokio::net::TcpListener` is not an axum `Listener`.
- `hyperbytedb/src/server.rs` — `serve_inner` is now `pub run_node(config, log_level, overrides, transport, shutdown)`; `serve` = `control::install` + SIGINT/SIGTERM task flipping `shutdown` + `run_node(.., TcpServeTransport)` + `control::shutdown`. Differences from the old `serve_inner`: (a) both routers are handed to the transport before startup sync / Raft formation, as `pending_router`s that answer 503 until the real router is set at the point the listener used to be bound (control: where it was spawned; main: Phase 1) — so in production the ports open earlier and answer 503 during startup sync instead of refusing connections, and TLS file errors fail before startup sync; (b) the SIGINT/SIGTERM handler is installed when `serve` starts, not at Phase 1, so a signal during startup now shuts down gracefully once startup completes instead of killing the process by default disposition; (c) the dead `api_shutdown_tx/_api_shutdown_rx` channel is gone (the `shutdown` receiver replaces it). Background tasks, startup sync, Raft, and the Phase 2/3 shutdown order are unchanged.
- `hyperbytedb/src/server.rs` — under `cfg(madsim)`, `serve` bails ("call run_node with a ServeTransport") — the sim has no TCP listeners or unix signals; the rig calls `run_node` directly.
- `hyperbytedb/src/bootstrap.rs` — `AdapterOverrides { points_sink, query_port }` + `build_services_with(config, overrides)`; `build_services(config)` = `build_services_with(config, AdapterOverrides::default())`. The chDB session/adapter construction moved verbatim into `open_chdb`, and the runtime-settings fallbacks (`set_config_fallbacks`, `query_pool_size`/`write_pool_size` fallbacks) now run before it (they never depended on chDB). A single override replaces only that port (chDB is still opened for the other). With **both** overridden, chDB is never opened and these steps are skipped as pure chDB housekeeping:
  - `create_dir_all(chdb.session_data_path)` — skipped; the directory is never created.
  - `DiskMonitorPaths.chdb` — points at `storage.meta_dir` instead (no chDB directory to stat; avoids a warning every check).
  - `catalog::prepare_cold_start_metadata` — skipped (rewrites chDB's on-disk catalog before session open).
  - `SharedSession::new_eager` (query and write pools) — skipped.
  - `query_pool_size` / `write_pool_size` settings appliers — not registered (no pools); their fallbacks are still set, so `SHOW SETTINGS` is unchanged.
  - `catalog::reload_persisted_tables` — skipped (ATTACHes chDB tables from on-disk metadata).
  - `ChdbQueryAdapter` and its `max_concurrent_queries` applier — skipped (the applier resizes that adapter's semaphore).
  - `ChdbNativeAdapter::warm_schemas_from_metadata` — routed through the port instead: `PointsSinkPort::refresh_schema_cache()` (the port's "warm schema caches from metadata" hook).
  - `ChdbNativeAdapter::warm_series_from_metadata` — skipped (that adapter's series-id dedup cache).
  - `ChdbNativeAdapter::sync_materialized_from_engine` — skipped (reads `system.tables` to set that adapter's materialization flags).
  Still running through the (overridden) ports: MV DDL reconciliation (`MaterializedViewService::reconcile_all`, via `QueryPort`/`PointsSinkPort`); WAL→sink recovery (the flush service drains unflushed WAL entries into `PointsSinkPort` on its first pass — there is no separate startup replay step); startup sync / Raft apply (given `app_state.points_sink`). `AppState.chdb_session_data_path` keeps the configured path (only read by backup/restore).
- `hyperbytedb/tests/*.rs`, `tests/compat`, `tests/e2e`, `tests/common` — `#![cfg(not(madsim))]` on every integration crate except `madsim_*` — they use real chDB, `axum::serve` on TCP listeners or `reqwest`; keeps `RUSTFLAGS="--cfg madsim" cargo clippy --all-targets --target-dir target/sim -- -D warnings` green.
- `hyperbytedb/benches/*.rs` — `#![cfg_attr(madsim, no_main)]` + `#![cfg(not(madsim))]` — real chDB (and `tokio::task::JoinSet`, absent from madsim-tokio); `no_main` because `harness = false` benches have no generated `main`.
- lib unit-test modules that bind TCP listeners or build a second runtime — `#[cfg(test)]` → `#[cfg(all(test, not(madsim)))]`: `peer_client` (`replicate_batch_tests`, `http2_tests`), `sync_client::tests`, `router::layer_routes_tests`, `heartbeat::tests` (+ its test-only `decide_transition`), `hinted_handoff::tests`, `forward_coalescer::tests`, `runtime::control::tests` (`Runtime::shutdown_background`), `shard_routing::scatter_tests`, `shard_scheduler::tests` (+ test-only `seed_rollup_dest`, `movers_in_flight`), `shard_transfer::tests` — same reason; production code is untouched.
- `hyperbytedb/Cargo.toml` — `madsim` as a `[target.'cfg(madsim)'.dependencies]` entry — needed by `MadsimRuntime` and `#[madsim::test]`; absent from production builds.
- `hyperbytedb/src/adapters/cluster/raft/madsim_runtime.rs` + `raft/mod.rs` — openraft `AsyncRuntime = MadsimRuntime` under `cfg(madsim)`, `TokioRuntime` otherwise (spawn/sleep/timeout via `madsim::task`/`madsim::time`, `MadsimInstant` newtype over madsim's clock, RNG from `madsim::rand`, oneshot from runtime-agnostic `tokio::sync`) — openraft's `TokioRuntime` calls real tokio, which has no reactor in the sim; Raft logic itself is unchanged.
- `Cargo.lock` — only additions over `main`: `madsim`, `madsim-tokio`, `madsim-macros` and their transitive deps, plus `hyperbytedb`'s `tokio` edge -> `madsim-tokio` and its direct `madsim` edge — resolved against chdb-rust `origin/main` like `main`'s lock; local working-copy lock drift from a stale `../chdb-rust` checkout (e.g. reqwest 0.11 / hyper 0.14 / openssl appearing) must never be committed.
